### Dashboard and UI correctness fixes (2026-11-04)

Five reported issues were confirmed in code and fixed locally:

1. **RouteProgress stuck at 82%** (`route-progress.tsx`): the click handler matched `closest("a")` including SVG `<a>` elements (the dashboard donut drill-downs), whose `.href` is an `SVGAnimatedString` rather than a string, so URL resolution threw or produced a garbage path that never matched the current pathname. Now only `HTMLAnchorElement` instances with a string `href` start the bar, plus an 8-second safety timeout that forces the bar back to idle when a navigation is cancelled or fails.
2. **Dashboard ignored the profile timezone** (`dashboard-overview.tsx`, `(app)/page.tsx`): period boundaries were computed on the browser's local clock, so "This month" and rolling windows could shift a day when the device timezone differs from the profile. `readDashboard` now resolves today's date via `Intl.DateTimeFormat` in the profile timezone (with a safe local fallback for missing/invalid stored timezones) and derives all range boundaries from that calendar date; the effect re-fetches when the timezone changes.
3. **Wrong currency flash**: the overview now receives the profile currency from the server (`currency` prop) like `displayName`, so the first paint formats with the user's currency; the flow legend no longer formats placeholder zeros before the payload arrives ("—" until data exists).
4. **AnimatedMoney assumed 2 decimals mid-animation**: `formatMoney` now defaults its fraction digits to the currency's real minor-unit count from `Intl.NumberFormat(...).resolvedOptions()` (2 for INR/USD, 0 for JPY, 3 for KWD, safe fallback 2 for unknown codes) via a new exported `currencyFractionDigits` helper, and AnimatedMoney's intermediate frames round to those same digits, so the final frame never changes format.
5. **Drawer modality**: the shell already locked body scroll and cycled Tab at the drawer's edges; the trap now also steers focus back into the drawer when focus has escaped to the background (e.g. after clicking the scrim), instead of allowing a Tab into the page behind it.

Also verified against the review checklist (no changes needed): `fillDailyActivity` and the calendar helpers operate on ISO date strings with UTC component math (no timezone parsing, month/leap boundaries safe); date-only strings never undergo UTC shifting anywhere in the dashboard or charts (noon-anchored parsing); the comparison delta returns "First period with activity" when the previous period is zero; analytics aggregation uses Decimal end to end (SQL `sum` cast to text for budgets/goals); every finance query filters by the verified profile (ownership verified in routes and by existing isolation tests); validation bounds amounts to positive ≤15 integer digits with ≤4 decimals and rejects out-of-range dates; logout calls `supabase.auth.signOut()` server-side (clearing the auth cookies via `@supabase/ssr`) behind a trusted-origin check; login has origin checking and Zod-validated credential limits; sign-in rate limiting and hosted-cookie caching remain configured on the hosted Supabase/Next layer and are unchanged.
